## Material changes since original HamClock

**High confidence:** [NWS Service Change Notice 26-21](https://www.weather.gov/media/notification/pdf_2026/scn26-21_Data_Format_Changes_Impacting_SWPC_Products.pdf) announces March 31, 2026 changes to Kp, flux and summary JSON, replacing header-plus-row/string values with numeric object arrays. It deprecates the old `/products/solar-wind/mag-*` and `plasma-*` feeds April 30, 2026. Their documented replacements are `/json/rtsw/rtsw_mag_1m.json` and `/json/rtsw/rtsw_wind_1m.json`. These preserve source identity and boolean active selection; old feeds did not. Wind names become `proton_density`, `proton_speed`, `proton_temperature`; mag keeps GSM components/Bt. Notice text spells a latitude replacement `theta_bsm`; the actual captured mag payload spells `theta_gsm`. Preserve that discrepancy in tests/research; do not implement the notice typo. Neither an old parser nor final-original feature parity proves compatibility with today's upstream formats.

[Current solar-wind product](https://www.spaceweather.gov/products/solar-wind) describes operational-quality observations, interruptions, dynamically selected spacecraft and a 24-hour static JSON source. It identifies SOLAR-1, IMAP, DSCOVR and ACE and warns of a display quality-flag limitation. This limitation is not evidence that JSON quality fields are absent: captured payloads include them. No flag interpretation or accuracy certification follows merely from their presence.

Actual mag/wind arrays ran newest to oldest with multiple spacecraft. Selection must use parsed time/source/active, not assume last row is newest or concatenate simultaneous spacecraft into one series. Mag sample contains negative Bz (legitimate signed field), while Bt is nonnegative. Do not reuse generic nonnegative-value rejection for components. Two channels at one GOES timestamp are separate observations, not duplicate timestamps.

[GOES product documentation](https://www.spaceweather.gov/products/goes-x-ray-flux) describes one-minute average short/long passbands, one-minute plot updates and eclipse/calibration dropouts, and explicitly links its numerical data directory and instrument-source mapping. Its GOES-R calibration differs from older satellites. X-ray flux is W/m²; long-band flux determines flare classification. **Medium confidence pending metadata review:** which wire value represents the exact displayed operational corrected quantity and how contamination should influence usability. Preserve all supplied numeric/contamination fields; do not invent correction equations from their names. Never add already corrected `flux` and `electron_correction` or choose observed flux automatically.

[Planetary K product](https://www.spaceweather.gov/products/planetary-k-index) describes an estimated three-hour index, one-minute chart updates and contributing observatories. Kp is a dimensionless geomagnetic index, distinct from integer local K, running a, daily A and predicted Kp. The linked [30-day daily geomagnetic text](https://services.swpc.noaa.gov/text/daily-geomagnetic-indices.txt) contains issued UT, dated rows, separate Fredericksburg/College/planetary columns and eight K values per day. It is a separate versioned grammar; do not infer the issue time is the observation time or silently substitute it for current Kp. [NWS static format-change example](https://services.swpc.noaa.gov/text/scn/fy26-03/noaa-planetary-k-index.json) independently agrees with the current four-key object schema.

For unit cross-checks, [SWPC ACE plasma text](https://services.swpc.noaa.gov/text/ace-swepam.txt) explicitly labels proton density p/cc, bulk speed km/s, ion temperature K, one-minute averages, status 0 nominal/1–8 bad/9 missing and negative missing-value sentinels. [ACE mag text](https://services.swpc.noaa.gov/text/ace-magnetometer.txt) explicitly identifies GSM/nT and −999.9 sentinel. **These are ACE text semantics, not automatically the new multispacescraft JSON flag/sentinel specification.** RTSW unit mapping to those conventional units is a proposed interpretation requiring peer product/metadata confirmation. Temperature additionally needs a Kelvin domain unit; the current snapshot enum's Celsius must not receive Kelvin unchanged. Until quality-code semantics are pinned, decode quality metadata losslessly without promoting these samples to `ReadingQuality::Valid`.

Zone-less timestamps appear consistently in current Kp/RTSW/flux feeds while GOES has Z. UTC interpretation is plausible from NOAA operational/UT context, but raw strings do not carry zone evidence themselves. Freeze explicit UTC interpretation per documented provider adapter, with reviewer confirmation; never use computer local time. Date-only/monthly products need separate interval types rather than arbitrary midnight/age substitutions.

## Source rights and cadence gates

[NWS reuse and appropriate-use policy](https://www.weather.gov/disclaimer) permits lawful reuse of NWS information unless noted otherwise, forbids claiming its material as one's copyright, false endorsement and portraying modifications as official material. It requires attention to timestamps, sensible request cycles and requests limited to needed data; error retries should be spaced at least a minute. Third-party content may have separate rights requiring the provider's terms. Preserve source notices and separate NOAA-supplied factual data from MIT implementation; no NOAA logo/endorsement. These statements do not grant blanket rights to all material hosted by NOAA.

[Solar-cycle product](https://www.spaceweather.gov/products/solar-cycle-progression) separately documents monthly means, smoothed and predicted fields, −1.0 for unavailable/uncomputable data, preliminary latest six months, SIDC sunspot and Canadian Penticton flux sources. Consequently neither its monthly values nor the terse summary clears SILSO/Canadian redistribution/derived-product permissions. Existing SILSO commercial-use and Canadian measurement rights research must be resolved per product; no permission laundering through a NOAA mirror. Kp uses several contributing observatories; capture product-specific source notices before distributing real fixtures. Source/attribution field alone is not rights proof.

Proposed replacement policies, **not provider guarantees**: shared GOES and RTSW refresh no faster than 60s; Kp may initially refresh 60s as its chart does, with later efficient cadence tuning; flux/daily text initially 1h until exact publishing schedule is verified. Retry 60/120/300/900s plus jitter, honor longer Retry-After. 403/404/auth or schema change becomes a stopped/error source requiring review, never alternate-host discovery. Source update cadence, HTTP rate authorization, cache validators and exact freshness-age limits remain independent contract fields; a one-minute plot is not a guarantee each JSON file updates every minute. No per-frame, per-widget or per-history-point fetching.

HTTPS transport requirements proposed for I03: exact allowlisted host/path product IDs, normal certificate verification, no downgrade/user URLs, zero automatic cross-host redirects (review new redirects explicitly), no credentials/cookies, cancellation and generation guards, bounded total/decompressed bytes, 10s overall/5s idle timeout, single request per feed, explicit Content-Type/status checks, aggregate concurrency 2. A proposed 4MiB decoded cap for RTSW wind and 2MiB mag gives finite room for measured current payloads but must be measured on Pi3; exceeding caps fails safely instead of expanding unboundedly. Unknown format gets Unsupported/Error with retained stale cache. Compressed input must be capped after decompression too. These are implementation choices for independent security review, not measured provider constraints.
