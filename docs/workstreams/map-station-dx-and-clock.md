## Proposed widget contracts: inputs, outputs, state and failure

All contracts in this section are proposed. A reviewer must reconcile each with the evidence index and original runtime before claiming parity. A single immutable station revision should feed all derived widgets; arrival of network data must not partially replace that revision.

| Widget | Inputs and commands | Output/state | Failure/offline/persistence policy proposed for implementation |
|---|---|---|---|
| Identity/location editor | Typed identity and axis-specific coordinates or locator; selected authoritative input; Save/Cancel; location-source choice. | Validated draft plus conversion explanation; exact committed coordinates and revision. | Invalid drafts remain editable; Cancel leaves memory/disk unchanged; persistence failure never looks saved. Manual saved coordinates work offline. Persist source mode separately from last fix. Do not overwrite a precise coordinate merely by displaying a rounded locator. |
| DE panel | Committed DE; real or preview instant; timezone policy; astronomy result; panel format. | Civil date/time, explicit zone/offset, locator and coordinates; event instant or interval; polar-event status. | Missing zone/ephemeris is a named unavailable state, never zero/default-looking data. Persist display format and timezone policy; independently confirm original restore scope. |
| DX panel | Committed DX; selected SP/LP; geometry, prefix lookup and time/astronomy results; optional satellite view. | Explicit route kind, distance/unit, bearing/reference and undefined status; distinct location and satellite modes. | Coincident/antipodal cases have explanatory status; unknown prefix stays unknown. Persist route/view preference without overwriting stored DX on satellite selection. Original exact satellite/DX state transitions remain to verify. |
| Main clock | Injectable wall-clock source, synchronization-quality evidence, preview offset/reset command. | Real UTC versus clearly labeled preview; date format; unknown/unsynchronized indicators. | Reading system time is not evidence of NTP synchronization. ## Primary protocol/data checks and constraints

**DXSpider:** [official receiving/posting guide](https://www.dxcluster.org/usermanual_en-4.html) describes received spots and SHOW/DX history; posting is a separate command with frequency/call/remarks. [Official command reference](https://www.dxcluster.org/usermanual_en-12.html) documents server filters including frequencies, calls and spotter attributes. A server-side filter and the application watch model are separate layers. Confidence high for these documents, medium for current dialect interoperability because the manual revision is old. AR/CC exact framing/login, charset and timing remain unknown and require their own primary documentation/recorded synthetic sessions. Read-only reception should be the first network slice; parse terminal escapes as inert text and cap lines, pending buffers, spots and reconnect attempts. A cluster operator's access terms and any redistribution rights still need checking; protocol documentation is not a blanket dataset license.

**Rig/rotator:** [Hamlib rigctld manual](https://hamlib.sourceforge.net/html/rigctld.1.html) describes newline-delimited text requests, value responses and `RPRT` errors, plus address/port configuration. [Rotctl reference](https://hamlib.sourceforge.net/html/rotctl.1.html) distinguishes position commands and daemon connections. Confidence high for documented protocol, unknown for the user's device capabilities. Implement against a local fake daemon first, with read-only PTT/position versus tuning/motion separated. No shared-library license decision is made here: independently review license if linking Hamlib; a separately written protocol client still needs command semantics and error tests. Do not silently start a daemon listening on all interfaces.

**Timezone:** [IANA](https://www.iana.org/time-zones) documents periodically updated civil offset/DST rules; checked release listing is 2026e. Confidence high for rules availability; **a lat/lon-to-zone geographic boundary dataset is a separate unresolved dependency**. Longitude-derived local mean time cannot substitute for civil timezone. Pin dataset/version/license and show the effective rule source; installed OS data may differ across Mac/Pi.

**GPSD:** [official JSON protocol, Overview and TPV/time](https://gpsd.io/gpsd_json.html) recommends libgps with protocol-version checks rather than a direct protocol client. TPV fields may be absent and responses truncated. Its UTC warning requires three consecutive 3D fixes; even then unknown current leap seconds can leave time several seconds wrong. Confidence high. Dependency review must compare libgps license/version/packaging on Mac/Pi against an explicitly justified direct adapter; this research approves neither installation nor fetching implementation. Proposed fixtures cover missing/nonfinite position, 2D/no-fix interruptions, three distinct 3D epochs rather than three messages from one epoch, unknown leap seconds, reconnect/version mismatch and truncated input. Location validity and UTC reliability remain separate; reject unusable values without changing committed station or sync state. Direct NMEA and serial/FIFO behavior need separate primary-source research. Never obtain root or alter host time merely to display device time.

**Orbit data:** [CelesTrak GP formats and usage](https://celestrak.org/NORAD/documentation/gp-data-formats.php) now defaults to CSV (May 9, 2026); request FORMAT explicitly. The current header reports six-digit IDs already in use since July 11, 2026, unavailable in TLE: OMM-compatible formats address a present compatibility gap. Final-original 4.22 behavior remains the parity baseline; current-feed compatibility is a separate acceptance requirement. Its guidance discourages checks more often than its two-hour update cadence and instructs clients to stop/report unexpected responses, especially 403/404. Confidence high; access guidance does not settle redistribution rights. Cache a successful bounded response atomically, retain freshness metadata, and keep HTTP failure bodies out of orbit parsers. Do not treat an old manual's endpoint as current. A propagator's license, test vectors and coordinate frames remain separate review tasks.

**Real map:** [Natural Earth terms](https://www.naturalearthdata.com/about/terms-of-use/) place its vector/raster data in the public domain. Current measured 110m land 4.1.0 bytes and hashes are in [verification](../land-dataset-verification.md); the website label differs. The frozen strict importer rejected tiny source boundary excursions. A separately reviewed endpoint-normalization increment must precede accepted data generation. Hole topology, Antarctica full-width closure and layer alignment remain rendering tests, not settled by matching version numbers. Existing coastline fragments must not be fabricated into land polygons.

**Dynamic overlays:** [NOAA D-RAP product](https://www.spaceweather.gov/products/d-region-absorption-predictions-d-rap) explains absorption products and links global frequency data. Confidence high for product meaning, unknown for the complete replacement ingestion/schema/redistribution contract. KC2G/GIRO, weather/clouds, RSS, city population, CQ/ITU boundaries and callsign-country datasets each require independent current terms, attribution and schema evidence. Avoid assuming an original author's permission, a public URL or an application MIT license covers third-party content.

**Logger UDP:** attempted official WSJT-X user-guide fetch failed in this pass. Its authoritative protocol document/source must be retrieved and pinned before implementation; no secondary article was used to fill wire-layout details. WSJT-X/N1MM/DXLog/Logger32/Log4OM are separate adapters, not interchangeable UDP. Explicitly disable control replies in the reception slice; source allowlisting is useful but unauthenticated UDP is still untrusted. Never claim all logger compatibility from one fixture.

Recommend bounded original math where reference evidence is clear; don't rename current equirectangular as Mercator to erase the gap.

Next: freeze D1/D2 synthetic protocol contracts and endpoint privacy policy; then fake-server integration/native replay before a user-chosen real connection. B runs a separate local adapter process with a small typed interface. Next: review process/dependency license, packaging and authenticated local IPC; then test crash/restart/backpressure and equivalent native error states. Recommend A for the first read-only dialect; postpone multi-dialect claims and hardware commands.
