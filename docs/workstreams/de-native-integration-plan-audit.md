## Required concrete header corrections

**Launch reentrancy:** launching settings intentionally enters a nested modal event loop while the dashboard's sole source timer and Big Clock view timer continue. Therefore a settings-launch in-flight guard cannot retain Big Clock's existing `updating_` guard throughout child `exec()`, or normal view refreshes would be rejected for the entire modal. Use a separate narrow launch guard, block recursive launches, require captured owners/dialog lifetimes to outlive callbacks and prohibit callback destruction of the parent. Refresh/update guards remain around their own one-getter transactions. Define behavior when refresh/setPreferences attempts to launch during an update: no recursive operation or partial controls. After child completion or launcher error, sample the latest envelope once and restore entry focus; launch exceptions must show a generic persistent action error without saying configuration was not applied or manufacturing a source failure. Actual outcome remains the trusted caller's source publication. Postcommit rendering failures remain outside recoverable rollback claims.

**Explicit exceptional unavailable publication:** 'production always provides context' must mean normal successful bridge generation, not an impossible guarantee after station-reset failure. The station editor returns only after disk save; if resetting the old DE owner fails, attaching its old location/manual context to the new saved station is false provenance. The future concrete envelope/caller needs an explicit failure/unavailable presentation path that removes old DE civil/context, clearly identifies the saved-station/reset error and does not substitute UTC. Generic absent context is unverified provenance, but is not by itself a complete semantic representation of a known production reset failure. Manual Apply must be disabled/rejected while the owner still belongs to the old saved location; it cannot quietly configure an obsolete station. Define the recovery path without public counter seeding or secretly replacing a live owner's revision namespace. Whole-owner exhaustion remains structural unless a proper injectable caller-operation boundary allows failure testing. No save rollback claim is allowed after disk commit.

**Present-context structural consistency:** validate complete config/policy/canonical location/positive reachable revisions; recognized UTC/DE/synchronization statuses; exact raw source presence/value copied into each result; manual payload matches requested mode; shifted encoding matches representable checked source+offset and is present only after addition; status-specific missing/Automatic/source-range/overflow/display-range/defensive failure/Ready field relationships; civil schema iff respective Ready; context digital actual fields and sync agree exactly with each raw result and envelope's actual fields; context preview is absent. Envelope preview may remain present but is explicitly independent of actual context. Preserve plain actual-versus-preview provenance text/AX. This validates shape/copies, not historical source authenticity or that arbitrary valid civil supplied by an untrusted caller corresponds to a timestamp. No Qt reconversion or new calendar proof routine is required in the view.

These are concrete API/source requirements, not permission to implement a second cache, async/session token mechanism, timezone mapper, persistence or broader source-quality policy. Root chooses a header and assigns exact existing files only after the corrections are explicit. There is no source-implementation gate yet.
