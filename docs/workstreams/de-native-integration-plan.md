## Concrete starting point

The dashboard's single one-second callback reads `QDateTime::currentDateTimeUtc()`, represents invalid source as absent, converts UTC and stores `BigClockDigitalInput` with missing DE/Unknown synchronization. Big Clock samples that owned input through one getter; its one-second view timer does not read OS time. Current Big Clock source description is opening-only and says DE is not implemented, so that string cannot describe later live configuration changes.

The native Big Clock Options panel controls display preferences and has guarded one-getter transactions. The new `DeClockSettingsDialog` owns draft controls and last-confirmed basis, never station/clock/settings state. Its Apply callback distinguishes Rejected, Applied, Unchanged and CommittedDisplayError and returns a confirmed owner snapshot; callback exceptions promise precommit rejection only. Outcome-unknown conditions require explicit reconciliation. Preserve that distinction when wiring it.

The station editor validates and prepares its returned snapshot before atomically saving disk state. The dashboard receives the result only after the save succeeds. Therefore a later DE reset/conversion error cannot truthfully be reported as a failed/rolled-back station save.

## One owner and one publication

Add one stable `DeClockConfigurationState` owned by the dashboard, initialized explicitly Automatic at the actual initial DE coordinates with caller policy `[-86400,+86400]` signed seconds. This is root's replacement UI bound, not an original limit. Owner is noncopyable/nonmovable; snapshots remain owned values. Keep session-only limitations visible, and do not add station-file fields in this increment.

Retain the sole callback's raw optional actual UTC as cached source. Keep explicit `SyncStatus::Unknown` until a separately reviewed evidence source exists. Replace independently published civil fields with one owned `DeClockDisplaySnapshot`: copied configuration, raw source, UTC/manual results and digital input agree because the frozen factory prepares them together. Prepare a full candidate first and publish by checked nonthrowing owned assignment; no independently refreshed provenance getter. A UTC read failure must publish missing-source evidence rather than keep an old numeric time looking fresh.

The Big Clock getter returns an owned coherent native value containing that digital input and its provenance. It must copy the last publication only: no independent UTC read, converter callback, provider request or event pumping. Every getter call during the modal event loop recaptures the current publication, rather than returning an opening-only captured value. Existing per-dialog update guards/lifetime requirements still apply; they do not make callback destruction safe. A separate settings-launch guard is required, rather than holding the update guard across a nested modal.

### Minimal next-header disposition policy

Propose exactly three native context dispositions: **CallerUnverified**, **Bound**, and **UnavailableAfterStationCommit**. CallerUnverified requires no bound context/failure record and displays queryable unverified-provenance text. Bound requires the coherent context and no failure record. UnavailableAfterStationCommit requires no old bound context and one fixed-size failure record containing a recognized reason (OwnerLocationResetFailed or DisplayPublicationFailed), the validated saved DE coordinates and raw cached actual-source evidence. It is not a new converter status: never report automatic unresolved/manual conversion failure as a substitute for owner-location mismatch.

For UnavailableAfterStationCommit, actual DE civil and any preview DE civil must be absent. Source/UTC evidence may be retained only with its matching owned raw source; if that preparation is unavailable, omit the numeric UTC too. Keep synchronization unchanged but expose an explicit DE unavailable/stale-context indication, distinct from UTC source accuracy. State visibly that the station was saved and DE time could not update. Disable launching/applying manual settings against the old owner's location until root reconciles the stable owner with the saved location; an old Getter snapshot or automatic desire cannot establish that reconciliation. No new revision counter or fake confirmed snapshot may be minted merely to paint a success state.

This envelope needs no asynchronous token or general fallback cache. It supplies the smallest safe representation for a failure the frozen conversion bridge cannot represent: the bridge requires a valid matching owner snapshot. Successful reconciliation must prepare a genuinely matching owner/publication before returning to Bound. Root must choose a concrete recovery path and separately test it; restarting/replacing the session is not silently assumed, and the settings dialog must not treat its old confirmed labels as the new saved station.

Two steps ahead: first migrate every native caller/regression and dynamically render provenance from the same envelope; second wire settings launch/apply and station-coordinate reset in the dashboard, with actual modal QA. If future automatic lookup becomes asynchronous, it needs a separate lifetime/request-generation/data-provenance contract; neither shape invents such authority. Shape A remains a valid smaller option only if root intentionally narrows the native API to bridge-backed actual time and separately handles preview fixture/API migration.

## Explicit Apply transaction

Within one serialized callback, capture the current owner snapshot and cached raw source once. Validate the requested desire using the immutable caller bounds and compare the expected draft basis to the same owning session's full current snapshot. A stale basis returns Rejected with current confirmed state and a bounded reason; it must not overwrite user draft or treat numeric revisions as global tokens.

For a valid different desire, prepare an owned candidate snapshot with that desire and checked configuration revision increment; same desire retains revisions. Prepare the coherent bridge output and all owned callback outcome/text data before changing the owner. Then call the existing checked `replace`, verify its returned confirmed snapshot matches the prepared candidate, and publish the prepared coherent output using a statically verified nonthrowing assignment. No other callback, event loop or worker mutation may interleave. Normal conversion/preparation failure returns Rejected with the unchanged owner.

After actual commit, Qt repaint or an unforeseen publication error cannot be represented as precommit rejection. Return truthful CommittedDisplayError with the actual confirmed settings and explicitly invalidate/mask DE display if coherent publication could not finish. Do not attach old manual civil data to a newly selected mode/offset. Ordinary fixed-size publication should be nonthrowing; this exceptional outcome is a truthful recovery path, not permission to publish half a bundle. Native editor remains open for Apply and supports explicit Reload under its reviewed contract.

Equal-value Apply may recompute from the same cached source and return Unchanged. It does not read the OS clock or reconfigure station persistence. Root can request an immediate Big Clock `refreshNow()` after closing the settings child (no new source read); during the child modal the existing timer continues reading only the latest whole publication. Setters/visibility alone do not erase pending action errors or timer state.

## Settings entry and dynamic provenance

Add one named >=44 logical-pixel “DE time settings” control inside Big Clock Options, not a new crowded dashboard masthead control. The injected launch callback opens the reviewed settings dialog using the same stable dashboard owner. Use a distinct RAII `launching_settings_` guard: block recursive launch (and launch during an in-flight view update), but do not hold `updating_` throughout the nested modal. Ordinary timer/manual refreshes must continue reading the latest envelope while settings is open. The launcher may not destroy the clock/owner, pump events inside an application transaction or perform concurrent writes; a modal event loop between serialized Apply operations is expected.

After normal close or launcher exception, sample/prepare the latest owned envelope exactly once through the existing refresh boundary, then restore focus best-effort. A launcher exception may follow a committed Apply; report a persistent generic action error without asserting rollback or that settings were rejected. Preserve that action error across successful timer/source refreshes under the existing explicit-action clearance policy; source recovery and settings outcome reconciliation remain separate. Optional/unavailable launch capability is explicitly disabled/explained for standalone synthetic views, and UnavailableAfterStationCommit disables old-location settings even if the callback exists. Freeze these outcomes before source edits.

Render a queryable plain-text provenance label from each successful native envelope: requested Automatic/Manual, automatic unresolved, missing source, fixed signed offset/no automatic DST, range/overflow/conversion reason, and session-only scope. Actual raw UTC remains distinct from shifted calendar encoding. Update visible text and accessibility name/description together whenever the publication changes; an opening-only description is insufficient. Preserve current clock stale/error behavior and separately retained action errors. No tiny spin arrows or color-only information; existing themes/font/touch tests remain gates.

## Saved station coordinates

After successful disk Save, compare actual saved DE coordinates against the owner using its canonical exact location semantics. Call `set_location` before publishing any civil value for the new location. A real DE change resets Automatic and advances both revisions; canonical dateline/signed-zero equivalence preserves manual desire. Callsign, DX or appearance-only saves must not reset DE. Invalid/cancelled/failed disk Save never reaches this reset.

Once disk Save succeeded, unexpected revision exhaustion/reset failure means station settings are saved but DE display is unavailable/error. Publish the explicit UnavailableAfterStationCommit envelope; omit old bound context and old-location manual/preview DE civil. Include the saved-location failure reason and disable Apply against the unreconciled old owner. Do not claim disk rollback or present the prior owner location as saved/current. A generic absent-provenance envelope is insufficient because it could permit old DE data to remain visible. Root must review a failure-injection seam around its integration operation instead of introducing a public counter seed or weakening production authority.
