# Local computer validation

October 2, 2026, development Mac, existing SDL2 compatibility installation.

The native program was opened as a local development app bundle through the computer-control tool. The running window showed system UTC and the offline foundation label. Clicking the first pane changed its visible title from SPACE WEATHER to BAND CONDITIONS without changing the other panes. The screenshot confirmed the old experimental font and schematic map remain in this executable; these are not the accepted production design.

The accessibility tree exposed the window controls but no application pane controls or readings. This is a concrete native accessibility gap. Escape was sent, but the immediate accessibility snapshot still showed the window; exit behavior was not confirmed by this computer test. Headless rendering and source-level Escape handling are separate evidence and do not establish interactive exit success.

The sandboxed command runner could not open a display; headless tests worked there. Terminal computer control was blocked by tool policy. Native testing used the development application directly, without changing the user's Terminal or live HamClock. The local app bundle is ignored build output, not a distributed package.

No Pi, touchscreen, browser-preview interaction, full accessibility walkthrough, resizing or full feature-parity test was completed in this pass. Each future UI increment requires a fresh local build and computer-controlled exercise of the changed behavior, with failures and untested portions recorded. Independent unit/regression audits precede draft PR publication; local GUI evidence does not replace target-device testing.
