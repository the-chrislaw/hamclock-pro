# Shared countdown service validation — October 11, 2026

CU1 adds an original, single-owner pure session service over the audited countdown model and stateless presentation. It owns one model/view and accepts injected monotonic timestamps; it reads no clock, activates no Qt UI or timer, schedules no alarm, operates no hardware, and performs no persistence, callbacks or network access. No default duration or original undocumented expiry/sound behavior is implied.

Every tick, command and acknowledgment prepares candidate model state, formatted view and owned return before no-throw commit. Reconfiguration validates duration/time order and increments a checked full-range configuration epoch before replacing the model with Idle/full duration/run zero. Even the same duration explicitly replaces and cancels an existing run/pending event; this is a replacement policy. Failed validation, allocation or identity exhaustion preserves the previous model, view, time, epoch and dismissal authority.

Only pending expiry snapshots issue opaque dismissal tokens. Tokens capture weak service lifetime identity, configuration epoch and run; stale, foreign, destroyed-lifetime or no-longer-pending tokens reject before advancing time. Weak identity guards authority without a global ID or raw-address-only comparison. The service is noncopyable/nonmovable and operations must be serialized. Weak tokens do not make calls through a destroyed service reference safe: a future native dialog must independently enforce its owner/service lifetime and timer callback context.

An additional 13 independent hostile sanitizer probes pass. Root configured/built locally, all 21 CTests pass (3.53 seconds), and executable makeverify passes. Checked configuration-epoch and run-counter helper exhaustion boundaries are exercised dynamically; their actual candidate-before-commit usage is independently source-audited. Full services were not driven through 2^64 reconfigurations/restarts, and no test-only restore backdoor or artificial lifetime cap was added.
