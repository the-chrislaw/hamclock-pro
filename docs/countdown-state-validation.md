# Countdown model validation — October 11, 2026

CT0 adds an original, injected monotonic countdown model and executable regression tests. It does not activate a countdown in the native UI, schedule a wall-clock alarm, operate radios/GPIO, play sound, fetch data or persist timers. The documented final-original minimum is one minute; the seven-day maximum and Stop/Resume/Reset/acknowledgment behavior are explicit replacement policies, not claims about the original numeric maximum or undocumented gestures.

Start explicitly restarts the full configured duration and allocates a fresh instance-scoped run identity. Stop advances then pauses if time remains; at or beyond expiry it remains Expired. Resume excludes paused time; Reset returns Idle and preserves the identity counter. Remaining time saturates at zero across valid ordered signed timestamp spans. Expiry becomes pending once per run, and acknowledging it cannot rearm it. Acknowledgment tokens must be bound to the same service lifetime: a new service may reuse numeric IDs. No cross-process identity guarantee is made.

Independent API review blocked the initial Boolean-only pending proposal because an old acknowledgment could clear a newer restarted expiry. The revised API adds full uint64 identities and explicit matching acknowledgments. Every Start invokes the checked next-ID helper on candidate state before commit; exhaustion rejects without wrapping. Stale/zero acknowledgment, invalid command, reversal and invalid resume preserve the complete state and last-observed clock.

Author strict warning/Address/Undefined sanitizer tests pass 61 permanent checks. Independent review passes those 61 plus 85 separate adversarial sanitizer probes with signed-span arithmetic oracle, stale acknowledgments, expiry boundaries and helper exhaustion. Root configured and built the current source locally, all 19 CTests pass (3.70 seconds), and executable `make verify` passes including the new countdown regression. No native UI code changes were made, so there is no new countdown computer-control acceptance claim. The existing native stopwatch UI retains its separately recorded validation.

The full-range helper is exercised dynamically at max-1/max and its actual Start commit use is independently source-audited. A service executing 2^64 restarts was not tested, and no public state-seeding backdoor or artificial small lifetime cap was introduced to manufacture that claim. The independent fresh whole-build result and final source/build hashes are recorded in workstreams/countdown-state-audit.md.

Actual Pi 3/Pi 4, minimum Qt 6.4, seven-inch touch, suspend behavior, countdown visuals/sound, persistence, concurrent service use, full feature parity and legal/accessibility certification remain untested or outside this slice. Caller owns monotonic clock injection and single-threaded service lifetime. Next slice is a separately audited presentation/control contract; any later native UI increment must pass actual computer-controlled validation before publication.
